# Discord-бот для управления организацией

Реализация на `discord.js v14` + SQLite (`sqlite3`), `dotenv`.

## Структура
```
project/
├── index.js       # обработчики команд, кнопок, модалок, select-меню
├── db.js          # обёртка над SQLite + схема таблиц + миграции
├── config.js      # ID каналов, ролей, иерархия, права
├── permissions.js # проверки прав (владелец/иерархия/ЧС/список участников)
├── members.js     # рендер списка участников (роли, паспорта, отпуск, AFK)
├── blacklist.js   # рендер чёрного списка
├── passports.js   # управление доп. паспортами (до 3 на участника)
├── dates.js       # разбор "7d" / "ДД.ММ.ГГГГ", форматирование
├── content.js     # текст правил и агитации по умолчанию
├── audit.js       # логирование действий в канал аудита
├── .env.example   # шаблон переменных окружения
└── package.json
```

## Установка
```bash
npm install
cp .env.example .env
# впишите DISCORD_TOKEN, CLIENT_ID и (опционально) GUILD_ID в .env
node index.js
```

## ⚠️ Обязательно включить в Discord Developer Portal
Помимо **Server Members Intent** (было нужно раньше), теперь дополнительно
нужен **Message Content Intent** — он нужен командам `/rules_update` и
`/agitation_update`, которые ждут от вас сообщение с новым текстом.
Включается там же: Developer Portal → ваше приложение → Bot → Privileged
Gateway Intents → Message Content Intent.

## Права бота на сервере
- Send Messages, Embed Links, Use Application Commands
- Manage Messages, Manage Roles, Manage Nicknames, Read Message History
- **Manage Channels** — обязательно для создания приватных каналов-профилей участников

## Контракты и статистика
При принятии/добавлении участника бот создаёт **приватный текстовый канал**
(не пост в форуме — Discord не поддерживает индивидуальные права доступа для
отдельных тредов/постов форума, только у обычных каналов это работает
надёжно) с названием вида `имя-фамилия-паспорт` в категории
`CHANNEL_PROFILES_CATEGORY`. Канал виден только самому участнику +
Владельцу/Зам. Владельцу/HR-Менеджеру + владельцу бота — через обычные
`permissionOverwrites`, это гарантированно работающий механизм.

**Обязательно создайте категорию** (ПКМ на список каналов → «Создать
категорию») и впишите её ID в `config.js → CHANNEL_PROFILES_CATEGORY`. Если
оставить плейсхолдер как есть — каналы будут создаваться без категории (вне
любой папки), это не ошибка, но менее аккуратно выглядит.

Боту нужно право **Manage Channels**, иначе создание профилей будет падать
с ошибкой (см. список прав ниже).

Старый канал-форум (`CHANNEL_CONTRACTS_FORUM`) для профилей больше не
используется — можно удалить его или использовать под что-то своё.

Участник присылает туда скриншот — бот отвечает тремя кнопками:
**✅ Выполнен** / **❌ Невыполнен** (оба варианта — это настоящий контракт,
просто с разным итогом, оба попадают в статистику) и **🚫 Не контракт**
(это вообще не контракт, просто скриншот — в статистику не попадает).
Доступны кнопки только руководству.

**Статистика — постоянное автообновляемое сообщение** в канале
`CHANNEL_CONTRACTS_STATS`, создаётся/обновляется командой `/init_menus` (как
список участников и ЧС). Кнопки на самом сообщении:
- ◀ Пред. неделя / Эта неделя / След. неделя ▶ — переключение недель
  (данные не удаляются, можно смотреть любую прошлую неделю).
- ➕ Добавить контракт / ➖ Удалить контракт — ручное управление (поиск
  участника по тегу/ID/паспорту/имени → выбор итога → ссылка на скриншот
  + дата).
- 🔍 Найти — посмотреть статистику конкретного участника за отображаемую
  неделю отдельным ephemeral-сообщением.

При любом действии (проверка скриншота, ручное добавление/удаление) —
сообщение статистики обновляется автоматически.

Роль бота должна стоять **выше** всех ролей из `config.js` (иерархия, AFK,
Отпуск), иначе выдача/снятие ролей и смена ников не сработают.

## Первый запуск
1. Пригласите бота на сервер с нужными правами.
2. Запустите `node index.js`.
3. Выполните `/init_menus` — бот создаст меню вступления/увольнения/отпуска,
   список участников и чёрный список. Доступно владельцу и роли `ROLE_PLUS`.

## Права и иерархия
- `OWNER_USER_ID` — неприкосновенен для действий других (нельзя уволить/
  изменить/поменять роль), и может пользоваться командами без роли `ROLE_PLUS`.
- `ROLE_ADMIN` — полный доступ без ограничений иерархии.
- Список участников (Добавить/Уволить/Изменить/Повысить/Понизить/Найти/
  паспорта/отпуск/AFK) — только `ROLES_MEMBERS_LIST_ALLOWED` (Владелец,
  Зам. Владелец, HR-Менеджер) + admin + владелец.
- Чёрный список — только `ROLES_BLACKLIST_ALLOWED` (Владелец, Зам. Владелец)
  + владелец (HR-Менеджер сюда НЕ входит).
- При повышении/понижении нельзя назначить ранг ≥ своего и нельзя управлять
  участником с рангом ≥ своего.
- Команды `/rules`, `/rules_update`, `/agitation`, `/agitation_update` —
  доступны тем же ролям, что и список участников.

## Отпуск и AFK
- «🏖️ Отпуск» / «✅ Снять отпуск» в списке участников — выдаёт/снимает роль
  `ROLE_VACATION` и показывает дату-время окончания под именем в списке.
- Самостоятельная заявка — кнопка в канале отпусков, идёт на рассмотрение
  с упоминанием ролей руководства; при одобрении участнику в ЛС приходит
  сообщение с кнопкой «Отменить отпуск».
- Срок задаётся как дата `ДД.ММ.ГГГГ` или относительно, например `7d`.
- «💤 AFK» / «🟢 Снять AFK» — аналогично, но только дата начала (без срока),
  роль `ROLE_AFK`, без выдачи/снятия при повышении-понижении.

## Несколько паспортов на участника (до 3)
Кнопка «📄 Паспорта» → выбор участника → добавить/удалить. Основной паспорт
(первый) хранится в самой записи участника и используется для ника и
поиска в первую очередь; 2 дополнительных — в отдельной таблице.

**Важное упрощение**: Discord не умеет рисовать настоящие таблицы в embed'ах.
Заголовок колонок показывается один раз сверху embed'а, у каждого Discord ID —
своё отдельное поле (доп. паспорта — строками внутри того же поля). Ограничение
Discord: максимум 25 полей на один embed, то есть на одну роль — до 25 разных
Discord ID одновременно видно в списке; при большем числе используйте 🔍 «Найти».

## Чёрный список
Отдельный канал, кнопки «Внести»/«Убрать»/«Найти». Если по Discord ID
найдено несколько паспортов — появляется выбор конкретной записи или
удаления всех, затем подтверждение перед фактическим удалением.

## Правила и агитация
`/rules` и `/agitation` публикуют текущий сохранённый текст (по умолчанию —
переданный вами). `/rules_update` / `/agitation_update` показывают текущий
текст (обычным сообщением + копируемым блоком ```), затем ждут ваше
следующее сообщение в этом канале (10 минут) и показывают предпросмотр с
кнопками «Сохранить» / «Отменить».

**Упрощение**: свод правил НЕ рассылается автоматически при каждом принятии
в организацию (чтобы не спамить канал) — только явно через `/rules`.

## Приглашения (кто кого пригласил)
В форме заявки на вступление поле «Онлайн в неделю» заменено на **«Кто вас
пригласил»** (необязательное, с подсказкой: Имя Фамилия / № Паспорта /
Discord тег или ID). При принятии заявки бот пытается найти этого человека
среди **текущих** участников (по ID, паспорту, тегу или имени) — если не
находит, приглашение просто не засчитывается, заявка всё равно принимается.

**Антифрод-правило (3 дня)**: приглашение засчитывается пригласившему только
если приглашённый пробыл в организации ≥ `INVITATION_MIN_DAYS` (по умолчанию
3) дней. Если человек выходит раньше — приглашение сгорает **и сам этот
человек больше никогда не может быть засчитан как приглашённый** (даже если
его пригласит кто-то другой и он останется надолго в следующий раз) — это
проверяется по Discord ID навсегда, запись в базе не удаляется. Если человек
никуда не уходит — приглашение подтверждается автоматически по таймеру
(проверка раз в час), не дожидаясь увольнения.

**Статистика — постоянное автообновляемое сообщение** в канале
`CHANNEL_INVITATIONS`, создаётся/обновляется командой `/init_menus`, формат —
по вашему примеру (пригласивший → список приглашённых с паспортами).
Кнопки: ◀ Пред. неделя / Эта неделя / След. неделя ▶ (неделя считается по
дате вступления приглашённого; данные не удаляются — можно смотреть любую
прошлую неделю), ➕ Добавить (поиск пригласившего → поиск приглашённого →
сразу засчитывается), ➖ Удалить (поиск пригласившего → список его
приглашений → выбор конкретной записи), 🔍 Найти (подтверждённые приглашения
конкретного человека за отображаемую неделю).

Доступ к статистике приглашений и заявкам — `ROLES_REVIEW_ALLOWED`
(Владелец/Зам. Владелец/HR-Менеджер), как и у контрактов.

## Синхронизация ника
При принятии в организацию / добавлении / редактировании участника бот
пытается выставить ник `Имя Фамилия | № Паспорта` (по основному паспорту).
Если у бота не хватает прав (роль ниже участника, либо это владелец
сервера) — ошибка тихо логируется в консоль, остальной процесс не прерывается.

## База данных — устойчива к добавлению/удалению функций
Вся схема БД описана **в одном месте** — объект `SCHEMA` в начале `db.js`.
При каждом запуске бот сам сверяет её с фактической базой: создаёт
недостающие таблицы, добавляет недостающие столбцы в уже существующие
таблицы, создаёт недостающие индексы. Ничего не удаляет и не переписывает.

- **Добавить фичу** → впишите новую таблицу или новый столбец в `SCHEMA`,
  больше ничего делать не нужно — при следующем запуске бот сам добавит их.
- **Удалить фичу** → просто не используйте её таблицу/столбцы в коде. Можно
  оставить их в `SCHEMA` (данные останутся целыми на случай, если функцию
  вернут) или убрать из `SCHEMA` — существующие данные при этом никуда не
  делись, просто бот перестанет их трогать.
- Никогда не редактируйте вручную `data.db` — риск разойтись со схемой.

## /ping — диагностика скорости
Ephemeral-ответ (виден только вызвавшему) с тремя цифрами:
- **WebSocket** — задержка heartbeat до Discord Gateway.
- **Отклик Discord (round-trip)** — время от отправки команды до получения её ботом.
- **База данных** — время выполнения простого запроса к SQLite.

## Прочие технические примечания
- Список участников для выбора (kick/edit/promote/demote/паспорта/отпуск/
  AFK) теперь сначала спрашивает текст поиска (Имя Фамилия или № Паспорта,
  можно оставить пустым) и показывает до 25 совпадений — так работает
  постранично, если участников много.
- Упоминания ролей руководства добавляются в сообщения новых заявок на
  вступление/увольнение/отпуск (не в чёрный список — там нет очереди на
  рассмотрение, действие сразу окончательное).
- `data.db` не нужно удалять при обновлении — миграции добавляют новые
  колонки/таблицы автоматически при старте.
