# Discord-бот для управления организацией «Freelance Company»

`discord.js v14` + SQLite (`sqlite3`), `dotenv`. Все команды и тексты интерфейса — на русском.

## Структура проекта (28 файлов)

```
project/
├── index.js                     # ядро: все 62 команды, кнопки, модалки, select-меню, таймеры
├── db.js                        # SQLite-обёртка + схема (SCHEMA) + автомиграции при старте
├── config.js                    # ID каналов/ролей, числовые настройки, иерархия рангов
├── config_store.js              # переопределение config.js через /настройка_изменить (хранится в БД)
├── permissions.js                # уровни доступа: hasBotAccess/isOwnerTier/isDeputyTier/isHrTier
├── command_permissions_sync.js  # OAuth2-флоу + синхронизация видимости команд в самом Discord
├── media_cache.js               # локальный кэш скриншотов на 30 дней (переживает удаление исходника)
├── dates.js                     # разбор дат (гибкие форматы), форматирование — всё по МСК
├── audit.js                     # логирование в канал аудита (структурированные поля) + logSystem
├── history.js                   # история выдачи/снятия отпуска и AFK
├── giveaways.js                 # розыгрыши: обычные, повторяющиеся, ЧС розыгрышей
├── passports.js                 # управление доп. паспортами (до 3 на человека), эффективная роль
├── members.js                   # рендер списка участников
├── blacklist.js                 # рендер обычной ЧС
├── contracts.js / contracts_display.js       # контракты + автообновляемая статистика по неделям
├── invitations.js / invitations_display.js   # приглашения + антифрод + статистика
├── acceptances.js               # подтверждение приёма (HR реально удержал человека N дней)
├── applications_display.js      # автообновляемая статистика заявок
├── faq.js / faq_display.js      # гайды FAQ через выпадающий список
├── content.js / content_versions.js          # правила/агитация/вакансия HR + история версий
├── week_revert.js               # автовозврат отображения статистики на текущую неделю
├── backup.js                    # ежедневный бэкап БД (gzip) в отдельный Discord-канал
├── csv.js                       # построение .csv для всех экспортов
├── clear-global-commands.js     # разовый скрипт очистки старых глобальных команд (не нужен в проде)
├── .env.example
└── package.json
```

## Установка

```bash
npm install
cp .env.example .env
node index.js
```

### Переменные окружения (`.env`)

| Переменная | Обязательна | Для чего |
|---|---|---|
| `DISCORD_TOKEN` | да | токен бота |
| `CLIENT_ID` | да | ID приложения, для регистрации команд |
| `GUILD_ID` | да | ID сервера (команды регистрируются на сервер, не глобально) |
| `DATA_DIR` | нет | куда класть `data.db`, бэкапы и кэш (по умолчанию — рядом с кодом) |
| `CLIENT_SECRET` | только для `/discord_права_настроить` | Client Secret из Developer Portal → OAuth2 |
| `OAUTH_REDIRECT_URI` | только для `/discord_права_настроить` | должен точно совпадать с Redirect, добавленным в Developer Portal |

## Discord Developer Portal — обязательные Privileged Gateway Intents

- **Server Members Intent**
- **Message Content Intent** — нужен для чтения скриншотов контрактов и текстов при обновлении правил/агитации/вакансии HR

Developer Portal → приложение → Bot → Privileged Gateway Intents.

## Права бота на сервере

Роль бота должна стоять **выше** всех ролей ранговой иерархии (`config.ROLE_IDS`), иначе выдача ролей и смена ников не сработают. Проще всего выдать роли бота **Administrator** — тогда всё работает автоматически (включая приватные каналы-профили, куда бот иначе не попал бы без явного разрешения). Если Administrator принципиально не хотите — как минимум нужны: Manage Roles, Manage Nicknames, Manage Channels, Send Messages, Embed Links, Attach Files, Read Message History, Manage Messages.

## Первый запуск

1. Впишите реальные ID каналов/ролей в `config.js` (или позже донастройте через `/настройка_изменить`, без правки кода).
2. Пригласите бота, запустите `node index.js`.
3. Выполните `/меню_создать` — инициализирует все меню, статистику и FAQ в нужных каналах. Доступно `+`/`.` (Admin).

## Система прав команд (62 команды, 5 уровней)

| Уровень | Кто |
|---|---|
| `owner_account_only` | буквально один Discord-аккаунт (Владелец), без обхода через любые роли — только `/discord_права_*` |
| `admin` | роль `+` или `.` (Admin) |
| `owner` | Владелец и выше |
| `deputy` | Зам. Владелец и выше |
| `hr` | HR-Менеджер и выше |

Полный список — команда `/права_команд` (показывает и переопределения). Любую команду можно точечно переназначить на другой уровень **или на одного конкретного человека** через `/права_команд` → «✏️ Изменить право команды» → выпадающие списки, включая настоящий Discord-пикер пользователя. Применяется мгновенно, без перезапуска.

`/помощь` показывает только те команды, которые реально доступны спрашивающему.

### Синхронизация видимости с самим Discord (необязательно)

По умолчанию недоступные команды **отвечают отказом**, но остаются видимыми в списке `/`. Если нужно, чтобы Discord вообще **не показывал** недоступные команды в автодополнении — есть `/discord_права_настроить` (одноразовая OAuth2-авторизация, нужны `CLIENT_SECRET` и `OAUTH_REDIRECT_URI`) → после неё видимость обновляется в Discord автоматически при каждом изменении через `/права_команд`. Статус — `/discord_права_статус`, принудительный пересчёт — `/discord_права_синхронизировать`.

## Профили и паспорта

У каждого паспорта (до 3 на человека) — свой приватный канал-профиль (`имя-фамилия-паспорт`), создаётся автоматически при принятии/добавлении. Виден только владельцу + Владельцу/Зам./HR + боту. `/профили_восстановить` чинит недостающие/архивные каналы и права доступа на существующих.

## Контракты

Участник присылает в свой канал два скриншота (взял → итог, в любом порядке отправки) — бот сам собирает пару **по каналу конкретного паспорта** (не по аккаунту — если паспортов несколько, у каждого своя независимая пара) и присылает карточку с кнопками ✅ Выполнен / ❌ Невыполнен / 🚫 Не контракт. Оба скриншота сразу скачиваются в локальный кэш (30 дней) — карточка не сломается, даже если исходное сообщение потом удалят.

**Авто-повышение**: 3+ обработанных контракта за неделю по конкретному паспорту у «1. Стажёра» → мгновенное повышение до «2. Фрилансер» (не дожидаясь понедельника). Выше «2. Фрилансер» — только вручную, через список людей.

**Авто-понижение**: каждый понедельник (по МСК, день недели настраивается) все паспорта на «2. Фрилансер» понижаются до «1. Стажёр». Принудительный пересчёт вне расписания — `/ранги_пересчитать_сейчас`.

Если контракт висит на проверке дольше `STUCK_CONTRACT_HOURS` (по умолчанию 24ч) — напоминание руководству прямо в канале контракта.

Статистика — автообновляемое сообщение с переключением недель, ручным добавлением/удалением (с выбором паспорта, если их несколько), поиском по человеку.

## Приглашения

Поле «Кто вас пригласил» в заявке на вступление. Антифрод: засчитывается только если приглашённый пробыл ≥ `INVITATION_MIN_DAYS` дней; если ушёл раньше — сгорает навсегда для этого Discord ID. Статистика — как у контрактов.

## Отпуск и AFK

Заявки от участников или выдача напрямую руководством. Гибкий формат даты: `ДД.ММ.ГГГГ`, `ДД.ММ.ГГ`, `ДД.ММ` (год — текущий по МСК), разделитель — точка/пробел/`/`. Прошедшие даты отклоняются. Кнопка «Вошёл(а)» в ЛС при выдаче AFK — самостоятельное уведомление о возврате (с защитой от повторной отправки), руководство подтверждает снятие отдельной кнопкой в канале `CHANNEL_AFK_RETURN`.

## Чёрный список — 2 отдельных списка

- Обычная ЧС организации — автообновляемый список, поиск, удаление.
- **ЧС розыгрышей** (отдельная) — `/розыгрыш_чс_добавить` / `_убрать` / `_список` — не пускает ни на самостоятельное участие, ни на ручное добавление, независимо от условия роли розыгрыша.

## Розыгрыши

`/розыгрыш_старт` — приз, длительность (`30m`/`2h`/`1d`/`1w`), победители, канал, необязательное условие (роль). Кнопка «🎉 Участвовать», ручное добавление/удаление участника, `/розыгрыш_реролл`, `/розыгрыш_отменить`, экспорт участников в CSV.

**Повторяющиеся розыгрыши**: `/розыгрыш_повтор_создать` (день недели по МСК + шаблон) — бот сам создаёт новый розыгрыш по расписанию, раз в день проверяет.

При создании — скрытое (spoiler) упоминание `@everyone`, уведомление уходит всем, сам пинг визуально свёрнут.

## FAQ, правила, агитация, вакансия HR

FAQ — одно сообщение с выпадающим списком вопросов на категорию (лимит Discord — 25 пунктов). Тексты правил/агитации/вакансии HR — с историей версий, предпросмотром перед публикацией (`/предпросмотр`, без реальной отправки) и подтверждением через кнопки.

## Настройки без правки кода

`/настройка_изменить <ключ> <значение>` — любое простое строковое/числовое поле `config.js` (ID каналов/ролей, пороги, интервалы). Автодополнение по ключам, показывает текущее значение. При вводе ID канала/роли бот сразу проверяет, существует ли он на сервере. `/настройка_показать` — что переопределено. `/настройка_переключить` — вкл/выкл приёма заявок / контрактов / напоминаний, без правки кода.

## Резервные копии и восстановление

Ежедневно в 23:59 по МСК — автоматический бэкап (gzip) уходит в отдельный Discord-канал (`CHANNEL_BACKUPS`), хранится на диске бота, старше `BACKUP_RETENTION_DAYS` дней чистится сам. `/бэкап_сейчас`, `/бэкапы_список`, `/резерв_восстановить` (откат к любому сохранённому, с подтверждением), `/резерв_загрузить` (заменить базу собственным `.db` файлом — тоже с подтверждением и автобэкапом текущей базы перед заменой).

## Аудит и системные логи — два отдельных канала

- **`CHANNEL_AUDIT`** — все действия людей (заявки, увольнения, контракты, ЧС, права, розыгрыши и т.д.), структурированными полями (кто/кого/причина/было-стало), не текстовым блоком. Полнотекстовый поиск с пагинацией — `/аудит_поиск`, экспорт в CSV — `/аудит_экспорт`.
- **`CHANNEL_SYSTEM_LOG`** — технические события самого бота: запуск/перезапуск, отключения/переподключения к Discord, сбой бэкапа, синхронизация прав с Discord, предупреждение о месте на диске. Не пишется в БД, не засоряет `/аудит_поиск`.

Удаление сообщений в других каналах тоже логируется — с полным содержимым, автором, реальным инициатором (проверяется через журнал самого Discord, отличает самоудаление от модераторского), и сохранёнными вложениями.

## Диагностика

`/пинг`, `/статус`, `/статус_бд` (размер файла + число записей по таблицам), `/кэш_статистика` (место, занятое кэшем скриншотов), `/сверка_ролей` (расхождения роль на сервере ↔ ранг в базе), `/поиск_везде` (поиск по 8 ключевым таблицам разом, с пагинацией), `/экспорт_бд` (все таблицы в CSV).

## Сводки руководству

Раз в сутки и раз в неделю Владельцу в ЛС уходит короткая сводка (новые заявки/увольнения, очередь на рассмотрение, просроченные контракты, кто заканчивает отпуск / итоги недели по контрактам-приглашениям-заявкам).

## Время — всё по МСК

Россия на постоянном UTC+3 без перевода часов — бот считает московское время фиксированным смещением, независимо от часового пояса сервера, где физически развёрнут. Влияет на: время ежедневного бэкапа (23:59 МСК), день недели авто-понижения, границы недели для статистики контрактов/приглашений/заявок, «сегодня» в сводках, разбор дат из форм.

## База данных — устойчива к добавлению/удалению функций

Вся схема — объект `SCHEMA` в начале `db.js`. При каждом запуске бот сверяет её с фактической базой: добавляет недостающие таблицы/столбцы/индексы, ничего не удаляет и не переписывает.

⚠️ SQLite не умеет менять `UNIQUE`-ограничение существующей колонки через `ALTER TABLE` — если такое когда-нибудь понадобится, нужна отдельная миграция (пересоздание таблицы), как уже сделано для `profile_channels` и `pending_contract_shots` в начале `db.js`. Никогда не редактируйте `data.db` вручную без крайней необходимости — используйте `/резерв_восстановить`/`/резерв_загрузить`, если что-то пошло не так.

## Известные ограничения

- Если хостинг делает жёсткое `SIGKILL` (без `SIGTERM`) — уведомление об остановке в системный канал не успевает уйти, это неизбежное ограничение, не связанное с ботом.
- Сообщение об удалении может не успеть сохранить вложения, если исходное сообщение удаляют быстрее, чем бот успевает скачать файл (доли секунды).
- Полная синхронизация видимости команд с Discord (`/discord_права_синхронизировать`) занимает ~70+ секунд на все 62 команды — у этого API-эндпоинта Discord строгий лимит запросов.
